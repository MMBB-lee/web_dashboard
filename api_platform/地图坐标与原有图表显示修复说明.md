## 原因与修复

1. C 的目录查询原来用省代码 `340000` 精确匹配地点的市级行政代码，导致总览缺少市级地点。现在按省/市层级筛选下属地区。
2. 目录能力、总览取点和前端曲线主要读取标准观测表，年度等公开统计保存在 `public_data_facts`，没有进入曲线。新增统一的原周期曲线读取，目录也能返回这些真实可用粒度。
3. 前端按当前年份或月/周固定窗口查询，遗漏原有日期及原始粒度。现在首次切换对象/粒度时使用已登记数据的统计时间。
4. 地图的数值字段曾有 `metric`/`latest_metric` 对接差异，交通地图还主动清空未选中对象的值；均已修复。地图浮层保留统计日期、数值和经纬度。

## 坐标来源与坐标系

- 机场来源：OurAirports 公开机场数据，记录各机场原始条目链接。
- 景区/铁路站来源：OpenStreetMap，经 Photon 检索并核对类型、名称及地区；景区用范围代表点、车站用站房或车站点位。
- 来源是 WGS84；数据库统一保存为 GCJ-02，与本项目 DataV 底图一致。`entities.location_note` 保存原坐标、来源 URL、转换后坐标系等溯源信息。
- 原始登记文件：`data_foundation/data_foundation/defaults/entity_coordinates.json`。
- 数据库写入验证记录：工作区 `tmp/geography-20261018/database-coordinate-verification.json`。
- 地图保留 OurAirports / OpenStreetMap 署名。OurAirports 公开数据为 Public Domain，OSM 数据按 ODbL 使用。

## 以后如何自动补坐标

原有 `scripts.import_public_data --apply` 流程已接入 `enrich_coordinates`：

1. 为新出现的景区/站点/机场登记地点身份，包括只有年/季度数据的地点。
2. 保留已经完整填写的坐标。
3. 对缺少坐标的地点优先使用项目坐标登记及本地缓存。
4. 新地点自动查询 Photon（可用 `GEOCODING_PHOTON_URL` 环境变量更换服务），校验名称、地点类型、安徽省及坐标范围。歧义或失败时保留为空并写入未解决清单，不填零或城市中心点。
5. 查询结果缓存，失败查询七天内不重复联网；网络查询位于数据库写事务之外。
6. 校验成功后写入数据库，转换为 GCJ-02，保留来源。原始数据包导入和种子目录也自动补齐登记内已知地点。
