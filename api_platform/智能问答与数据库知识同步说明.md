# 智能问答与数据库知识同步（2026-10-18）

## 使用

刷新前端，进入“智能问答”。模型先根据当前问题和最近对话判断是否需要项目资料：通用常识、闲聊、写作等直接回答；项目问题再检索知识文档，具体客流问题还会调用只读数据库查询。没有相关资料时仍由大模型自然说明或追问，不再固定返回“证据不足”。原有流式输出与停止按钮保留。

进入“知识库管理”，点击“更新数据库”，即可将新增或变化的地点、指标、客流、假期、事件整理为可检索资料。按钮会自动启动索引处理，不必另开命令行 Worker。状态中的“可检索”数量与资料总数相同后即可使用。数据导入、爬虫同步后再次点击此按钮更新 RAG。

当前实库已完成70篇业务资料的首次同步，覆盖25225条业务记录。原有16篇文档继续保留。同一内容重复同步不生成新文档、不重新索引；内容变化生成可追溯的新版本，新版就绪后检索切换到新版。旧版本仅留作历史记录。

## 数据口径

数据库导出的文档保留指标、单位、统计期、来源及公开/估算/模拟/待核验标记。模拟数据不会改称官方实测，历史月报不能作为实时人数。数据库同步只读取业务字段，账号、密码、会话和运行配置不参与知识构建。原来的业务表内容不因点击同步按钮改变。

项目数值查询限定在服务端的地点与指标目录内，不执行模型生成的SQL。回答引用由服务端附加，仅展示回答实际引用的来源。

## 实现与验证

- `app/services/assistant_agent.py`：模型意图规划、只读数据库工具、最近对话及引用筛选。会话按登录用户隔离，最多保存最近5轮，空闲2小时过期；服务重启会清除这部分临时对话记忆。
- `app/services/database_knowledge.py`：业务字段导出、内容指纹比对、正常索引队列发布。沿用C的`knowledge_documents`、`knowledge_indexes`、`knowledge_chunks`等表和E的解析/检索流程。
- `POST /api/v1/knowledge/database/sync`：管理员及CSRF校验；`GET /api/v1/knowledge/database/status`：同步状态。
- 前端`KnowledgeManager.vue`提供同步入口，原有上传与重建索引入口保留。

实际浏览器已验证“你打算”、常识解释、未知景区实时人数、万佛湖2026年9月数据库查询均正常流式输出。万佛湖返回83907人次并识别为模拟数据；未知项目问题无固定拒答，通用问题无无关引用。重复同步70篇全部跳过。后端相关回归测试、前端39项测试及构建通过。

本机仍使用既有OpenAI兼容大模型配置，密钥只在后端环境配置中保存。
