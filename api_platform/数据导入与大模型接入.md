# 本地数据导入与 OpenAI 兼容大模型接入

本扩展不修改账号或密码、不清空原始库。爬虫 SQLite 使用只读连接。导入所有来源记录，并保留候选、原始周期和口径；不把年度/季度/累计/假期拆成日周月。

## 1. 运行位置

所有下面命令均在 PowerShell 的本目录运行：

```powershell
cd "D:\李墨白\比赛项目\数字媒体\项目++++\api_platform"
```

使用项目已有 Conda 环境 `..\.venv\python.exe`，无须安装全局 Python。本次已安装 httpx；以后重装环境可运行 `..\.venv\python.exe -m pip install -e .`。

## 2. 预览、迁移与导入

```powershell
..\.venv\python.exe -X utf8 -m scripts.import_public_data --report .\data\public-import-preview.json
..\.venv\python.exe -X utf8 -m scripts.import_public_data --apply --migrate --report .\data\public-import-result.json
```

默认读取同级爬取工具的 `data/local/crawler.sqlite3` 和 C 的 `real_data/2026-10-12-v2/manifest.json`。可用 `--crawler-root`、`--manifest` 显式覆盖。未传 `--apply` 不连接目标业务库。传 `--apply --migrate` 后先以 D 配置的同一连接串迁移，再幂等补齐 C 基线的观测/文档/假期/事件，最后执行转换导入。

这次快照输入245条：145条爬虫事实、83条C观测、17条C补充事实。245是来源记录数，包含不同来源或交付包的重叠事实，不是可相加的互斥统计量。

增量迁移名是 `local_public_data_01`，新增 `public_data_facts` 和 `public_data_imports`。它不是上游视频迁移0007，不包含 `uow.visible`。

- `public_data_facts`：全部事实、原单位/原周期、原记录、出处、摘要、质量、受管理原件引用与历史修订。
- `public_data_imports`：每次实际导入的审计与统计。
- `observations`：只增加符合当前业务指标和日/周/月/假期规则的核验数据；来源冲突、单位未确认或既有值变化不覆盖，事实继续保存在公共事实表。
- 与原始 C 观测对应的同一原件/周期/值会关联原记录，避免引入多来源重复导致原曲线冲突。
- 年度、季度、累计及背景指标保留在公共事实表，不混入现有周/月图。
- 首次从现有83条观测出发，隔离MySQL实测得到245条公共事实、175条普通观测。以后采集数据变化时数量会变化。

所有引用的原件在导入前校验 SHA-256 和大小，复制到 D 的 DATA_DIR 管理目录；源 SQLite 不修改。重跑相同事实跳过，变化留历史。候选和 `pending_scope_confirmation` 保留为 `pending_review`，不能当核验值。

```sql
SELECT entity_name, metric_code, grain, period_start, period_end,
       value, unit, quality_status, source_url
FROM tourism_flow.public_data_facts
ORDER BY entity_name, period_start;

SELECT entity_name, metric_code, grain, value, unit, quality_status
FROM tourism_flow.public_data_facts
WHERE entity_type = 'scenic';
```

## 3. 大模型配置

本机 `.env` 已追加占位项，默认关闭，不含密钥。编辑本目录 `.env`：

```dotenv
LLM_ENABLED=true
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=填写自己申请的密钥
LLM_MODEL=deepseek-flash
LLM_TIMEOUT_SECONDS=60
LLM_MAX_TOKENS=4096
```

DeepSeek 示例依据 https://api-docs.deepseek.com/ 。其他 OpenAI 兼容服务应使用该服务实际提供的模型名、Base URL 和密钥。Base URL 可为 `https://服务地址/v1`，代码自动追加 `/chat/completions`，也支持完整 endpoint。密钥仅由服务端读取，不进入前端。

主动测试一次真实API连接：

```powershell
..\.venv\python.exe -X utf8 -m scripts.check_llm
```

未配置密钥或模型时给出明确错误；401/429/超时等不会把密钥或上游响应正文返回给浏览器。

## 4. 重启后端并使用

先在原API和Worker窗口按Ctrl+C。再各开一个终端，在本目录运行：

```powershell
..\.venv\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

```powershell
..\.venv\python.exe -m app.worker
```

前端保持API模式，从智能问答页提问，例如“黄山2025年进山量是多少”“九华山2025年春节接待多少人”。后台从问题中选择对象和年份，从导入事实表取证据，再调用兼容接口；来源引用由服务端附加。明确的结构化数值请求仍沿用原完整周期与缺期检查。没有证据不调用模型编造客流，当前/实时问题不会自动拿历史年报作当前值。未启用模型时保留原E检索流程。

目前未自动建立16份文档的E索引。事实问答可以使用新导入表，运营时间等说明性问题仍需要独立建立知识索引。现有景区周/月图不会因为导入年度事实就自动出现曲线，展示这些原周期需要另外扩展页面。
