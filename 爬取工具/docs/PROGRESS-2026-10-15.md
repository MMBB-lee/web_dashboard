# 全省采集第二步：独立机场批次交付

日期：2026-10-15。已按用户要求取消与团队 D/E 联调的绑定。采集器是独立本地 Git 工程、独立可安装包、独立数据库与命令；没有修改 D/E 仓库，没有向团队作业表入队。尚未创建远端仓库，不将此代码推入团队 C 仓库。

SQLite保留在 `data/local/crawler.sqlite3`。MySQL在本轮专用、关闭网络监听的临时实例中运行，验证后关闭但不删除库和文件；它不是已部署的共享生产服务。表结构为独立schema_version=1 / 8张ac_表，未动团队0006/31表。

机场解析按样本原表核对后限定为“旅客吞吐量/本期完成”；保存原单位“人”、标准吞吐人次、页/行/列及原句，避免取名次、累计或货邮量。`validated` 是程序结构/来源/周期校验状态，不宣称所有260个数值逐条人工审查。首次网络失败的证书链问题、原始失败记录和补齐公共CA后成功记录分别保留，未关闭TLS或绕过robots。

## 仍然存在的缺口

- 合肥、黄山、阜阳、芜湖、安庆、池州各41个月，均缺2023/2024/2025年12月。
- 亳州9个月，已观察窗口内仍缺2025年12月；蚌埠滕湖5个月。首次已见月份不是实际通航日期，之前不填0。
- 城市/景区/铁路目前只有台账和部分原件归档，数字适配仍需逐源开发。35份非月报原件没有冒充已核实月度事实。
- 本轮只验证已采到2026年8月，不宣称已取尽现在所有最新公开资料。在线目录有明确页数/报表预算，尚需后续扩大历史发现。
- 定时增量、游标/条件请求与完整失败恢复属于第三步，尚未启用常驻后台任务。

## 下一批顺序

继续在本采集器内做：机场12月原件定位 → 九市年度公报字段适配 → 万佛湖/九华山等景区假期专题 → 合肥南/芜湖/阜阳西等站点实绩 → 剩余入口与受限来源登记。年份、累计、约数、站群、预计值各自保留原定义，不能为凑完整率变成精确月值。

不等待D的Worker或E算法完成。采集器只生产数据包；下游项目是否/何时导入、展示或建模，由下游另行决定，不反向阻塞本项目。
