1. **机场缺期**：六个既有机场仍缺2023/2024/2025年12月的独立月值；亳州已观察窗口内缺2025年12月。优先发现确切月值原件或正式公告，不由年累计减11月累计推导。核对新机场实际统计起点，首次已见行不等于通航日。
2. **城市公报**：上述9市已完成首批17条，详见[城市批次验收](../acceptance/2026-10-15-bulletins/README.md)。年度交通量与年末存量分开；池州范围未明确的旅客总量未入库，市级铁路数据未套单站。继续补旅游接待、花费/收入等确有公开数值的指标；无值不填零。
3. **景区专题**：万佛湖2025五一五天总量优先；九华山春节范围、天堂寨年份、琅琊山约数逐项复核。约/余/超过保留限定语，留候选层，不能当精确值。宏村西递合计不拆成两个单景区。
4. **铁路专题**：合肥南站、芜湖站、阜阳西站的已有单日实绩优先，旧黄山北站资料可迁入。严格区分单站/直属站、发送/到发、预计/实际；不把车票余量、列车班次数当旅客量。
5. **补齐剩余来源**：合肥、蚌埠、黄山城市公报及采石矶等继续定位原件。412/403/验证码等访问限制记录，不使用绕过或高频重试；一个站点失败不阻塞其他来源。

天气、预警和地图是后续辅助源，需明确账户/许可再接，不是当前公共统计数据回补的阻塞。轨道网络和省外对照不挤占上述已审计核心对象。

## 已固定的边界

- 独立包名 `anhui-public-data-crawler`、命令 `anhui-crawl`，不导入 `data_foundation`、D的`app` 或 `intelligent_analysis`。
- 独立 MySQL schema `anhui_crawler*`，只含8张 `ac_` 表；不修改团队0006/31表，不占用团队jobs，不需要D/E配合发版。
- 默认CSV/JSON数据包是消费边界；未来其他项目的导入适配是可选下游工作，不反向阻塞本采集器。
- 审计台账允许城市、机场、景区、铁路站；存储层原生支持 day/month/year/holiday/cumulative，不为兼容旧API而改写年/季/累计事实。季度可先保留候选，新增该粒度时需单独校验规则。
- 不自动开户、不购买API、不发送数据申请、不发布原件全文、不启用后台周期任务。
