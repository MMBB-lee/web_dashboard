# 完整实施与验收跟踪

更新日期：2026-10-16。当前实现版本0.3.0a1，尚未发布1.0.0，完整计划尚未验收完成。

## 用户已确定的验收范围

- 44对象：16市、8机场、12景区、8铁路站。来源从原33个扩为34个，新增安徽日报黄山北站来源，未增加研究对象。
- 历史从2023-01-01至最终验收截止时间（北京时间）。保持原生周期、统计范围、原单位与限定语。
- 采用公开数据闭环：可得的有效资料处理完；确实不可得的项目有检索证据、原因和下次检查时间。审计覆盖率、资料处理率、数值/时间覆盖率分开报告。
- Mac与Windows均须真实安装、SQLite/MySQL、采集、恢复和原生调度验收。Windows由用户方运行验收包回传，未收到合格回执不得宣称双端通过。
- 日常只选一台采集主机，默认Mac。包含真实定时触发与失败恢复。独立于团队C/D/E。

## 当前真实数据口径

- 机场：260个月值，2023-01至2026-08；已通过公开目录及文档队列重跑，全部去重。六机场2023—2025年12月及亳州2025年12月仍无独立月值；不做累计差分。
- 九市公报：17条2025年度交通/年末存量。没有把景区数量当游客量，也没有把市域铁路值套给单站。
- 万佛湖2025五一五天、九华山2025春节：精确接待量，保留假期整体周期和发布范围。
- 合肥南站、阜阳西站、芜湖站：明确单站日期实绩；芜湖4月5日“超过”及琅琊山“约”保留候选。
- 黄山年报：2023—2025年度进山量，独立指标scenic_mountain_entries，原单位“万人”换算为“人”，不混入索道或宣称去重游客。2023来自2024年报明确列出的上年同期值。
- 黄山北站：2025-01-01至06-30发送量，cumulative精确区间，locator保留half_year原生说明；不含全市6站、到达或到发量。

## 软件与数据缺口，不得以测试通过替代

1. 城市2023/2024年度历史及旅游接待、收入/花费尚未完成。当前城市规则为9市已审阅模板；指标字典中存在的指标不等于已实现所有来源提取。
2. 剩余城市/景区/站点需要来源查找、发布主体核验、格式适配及两轮检索证据。现有33个旧来源已经本轮联网检查，但这不是44对象全部历史资料审计完成。
3. 当前发现器只沿配置入口与明确链接续采；尚无每个对象的完整官方栏目配置。已解析文章的旧固定URL不能替代未来新公告发现。
4. 城市PDF/Word附件仍归档待核验，不能作为已完成其新增字段提取。来源只提供未支持格式时仍属于适配缺口。
5. 机场实际统计起点、未发布与缺原件仍需逐项证据；首次观察行不等于通航日期。
6. Windows包安装、双数据库、原生调度和恢复待实机回执。Mac任务在Documents目录第一次未及时产出，迁到Application Support后受控验收通过；保留失败记录。
7. 完整验收需逐目标导入审阅过的audit证据。程序不自动把“有一条事实”当作整个历史窗口完成。

## 后续执行顺序

1. 将城市官方栏目而非仅单篇公报纳入显式台账迁移，逐年回补2023—2025公报；完善旅游数值和PDF附件适配。每批经过原件定位、幂等、SQLite/MySQL与覆盖核验。
2. 对12景区和8站逐项检索主责主体、属地政府及公开搜索；保存搜索词、年份、范围、URL、时间、原件或失败。对无法取得的资料在冻结前再次复查，禁止把解析缺陷归为无数据。
3. 完善逐指标/周期的缺口结论与新鲜度；配置季度、年度及假期发现入口。预算耗尽继续队列，不能据此认定不存在。
4. 用户方用同一wheel在Windows执行Run-WindowsAcceptance.ps1 -RequireMySql -WithScheduler，回传脱敏回执、测试XML、数据库版本及原生调度证据。
5. 固定截止时间，运行verify --final，只有全部门禁通过才制作1.0.0。
